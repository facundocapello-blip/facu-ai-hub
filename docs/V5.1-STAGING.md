## Reproducción

Node 22 recomendado; Node 24.19.0, Java 21 y Chromium del sistema validados.

```sh
npm ci --cache /workspace/.cache/npm
npm ci --prefix functions --cache /workspace/.cache/npm
npm test
./scripts/staging-build.sh
CI=true npm run test:e2e
XDG_CONFIG_HOME=/workspace/.config FIREBASE_EMULATORS_PATH=/workspace/.cache/firebase CI=true npm run test:auth
XDG_CONFIG_HOME=/workspace/.config FIREBASE_EMULATORS_PATH=/workspace/.cache/firebase CI=true npm run test:rules
XDG_CONFIG_HOME=/workspace/.config FIREBASE_EMULATORS_PATH=/workspace/.cache/firebase CI=true npm run test:cloud
```

Las pruebas de reglas y cloud usan `demo-facu-hub`; no crean recursos cloud ni usan datos reales. La descarga oficial del emulador requiere `storage.googleapis.com`; no desactivar TLS ni checksums. Para desarrollo local ejecutar `VITE_LOCAL_ONLY=true npm run dev`.

El workflow `staging-checks.yml` ejecuta las mismas suites y conserva un artifact. El primer run completo aprobó: https://github.com/facundocapello-blip/facu-ai-hub/actions/runs/39967540396. Los resultados más recientes están en Actions y en el PR del piloto.

## Publicación de este preview

El sitio está servido por raw.githack.com desde la rama pública de build; no usa Pages ni un proyecto de hosting pago. Es un CDN de preview sin garantía de disponibilidad; su caché puede demorar actualizaciones. La URL fijada al SHA del commit de build evita mezclar revisiones y permite volver a un preview anterior sin cambiar archivos. `staging-info.json` permite comprobar el commit fuente del build publicado.

```sh
VITE_CDN_PREVIEW=true VITE_BASE_PATH=./ ./scripts/staging-build.sh
```

`VITE_CDN_PREVIEW=true` excluye los PNG y el manifest de la precaché: el CDN redirige estos archivos a GitHub Raw y Workbox rechaza respuestas redirigidas a otro origen. El manifest mantiene sus iconos para carga online; los iconos de instalación offline no están garantizados en este proveedor. El build normal conserva su precaché completa.

Publicar solo `dist` en `staging-v51-dist`, conservando historial y sin modificar `main`. No incluir `.env`, credenciales, datos de usuario ni archivos del servidor. El commit de build debe indicar la revisión fuente en `staging-info.json`.

Rollback del piloto: volver la rama de build a un commit anterior mediante un commit nuevo y dejar vencer la caché. V5.0 sigue en `main` y su publicación de Pages no se modificó; no necesita redeploy. Conservar respaldos originales.

## Firebase y límites reales

La implementación conserva Auth/Firestore y admite los campos opcionales V5.1 en validadores, respaldos y `firestore.rules`; las pruebas de emulador verifican permisos y persistencia offline. **No se publicaron reglas sobre producción.** Para habilitar sincronización en el preview se requiere un proyecto Firebase de staging separado y desplegar allí estas reglas. Las reglas V5.0 rechazan los campos nuevos.

Firebase CLI no tiene sesión de despliegue. GitHub rechazó crear un repositorio Pages separado con HTTP 403 “Resource not accessible by integration”; el token existente sí permite trabajar en este repositorio. Esas limitaciones no impiden el preview local-only ya publicado.

Alternativa futura: Firebase Hosting preview en cuota gratuita Spark, con sesión autorizada, usando únicamente `firebase hosting:channel:deploy` y sin activar Blaze ni Functions. No ejecutar un `firebase deploy` global ni publicar reglas sobre el proyecto estable para probar este piloto.

Pendientes: Safari físico en iPhone 15 Pro Max (teclado, modales, instalación, enlaces de chat, reapertura offline) y sincronización pública con Firebase de staging si se necesita. La continuidad con ChatGPT es manual: copiar/pegar el resumen y abrir el enlace no transfiere contexto ni historial.
