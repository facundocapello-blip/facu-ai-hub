## Preparar y probar

Node 22 recomendado; Node 24 validado en el entorno. Java 21 y Chromium disponibles.

```sh
npm ci --cache /workspace/.cache/npm
npm test
./scripts/staging-build.sh
CI=true npm run test:e2e
XDG_CONFIG_HOME=/workspace/.config FIREBASE_EMULATORS_PATH=/workspace/.cache/firebase CI=true npm run test:auth
XDG_CONFIG_HOME=/workspace/.config FIREBASE_EMULATORS_PATH=/workspace/.cache/firebase CI=true npm run test:rules
XDG_CONFIG_HOME=/workspace/.config FIREBASE_EMULATORS_PATH=/workspace/.cache/firebase CI=true npm run test:cloud
```

El build de piloto usa IndexedDB local y desactiva el endpoint opcional de IA. No se conecta al proyecto Firebase estable. Exportar desde V5.0 e importar en el piloto permite probar una copia de los datos; los orígenes HTTPS no comparten IndexedDB. No se escriben datos reales automáticamente.

La implementación conserva Auth/Firestore y agrega campos opcionales compatibles con respaldos V5.0. `firestore.rules` admite esos campos, pero **no se publicaron reglas sobre producción**. Probar sincronización con emuladores o un proyecto Firebase de staging separado; las reglas V5.0 desplegadas rechazarían los campos nuevos.

## Publicar sin reemplazar V5.0

Se necesita una sesión Firebase autorizada y acceso de red al servicio. Firebase Hosting tiene cuota gratuita en Spark; no activar Blaze ni Functions. Después de compilar y probar, publicar únicamente un canal preview:

```sh
./scripts/staging-build.sh
npx firebase hosting:channel:deploy v51-issue-1 --expires 7d --project facahub --non-interactive
```

Este comando propone un canal temporal separado del canal `live`; no ejecutarlo como `firebase deploy`. Usar la URL HTTPS devuelta por el CLI, no inventar una URL. Comprobar HTML, recursos, manifest y flujo móvil contra esa URL. El canal expira en siete días y debe renovarse. Como alternativa, usar un sitio/repositorio gratuito separado indicado por el propietario.

Rollback del piloto: dejar expirar o eliminar solo el canal preview. V5.0 sigue en main; no necesita redeploy. Conservar los respaldos originales: cualquier importación posterior a V5.0 debe revisarse, pues sus reglas no admiten los campos nuevos.
